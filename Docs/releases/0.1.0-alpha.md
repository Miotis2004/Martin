# Martin `0.1.0-alpha` Release Notes

**Release:** `0.1.0-alpha`  
**Recommended tag:** `v0.1.0-alpha`  
**Language version:** `0.1`  
**Manifest schema:** `1`  
**Studio MSIX version:** `0.1.0.0`  
**Generated project default framework:** `net8.0`  
**Release date:** 2026-07-18

## Summary

Martin `0.1.0-alpha` is the first public-alpha release candidate for the Martin Programming Language: an experimental, statically typed language for the .NET ecosystem with compiler, runtime, CLI tooling, language services, project-system support, sample projects, and the WinUI-based Martin Studio IDE.

This alpha is intended for evaluation, documentation review, sample experimentation, packaging validation, and early feedback. It is not a production-ready release and does not promise source, binary, diagnostic, package-layout, runtime, generated-C#, or Studio compatibility across future alpha versions.

## Intended audience

Use this alpha if you want to:

- Try the documented Martin language subset.
- Validate `martin` and `martinc` .NET tool workflows.
- Review compiler diagnostics, generated executable output, and runtime behavior.
- Explore Martin Studio as a Windows x64 single-project alpha IDE.
- File actionable bugs, documentation corrections, packaging issues, or design feedback.

Do not use this alpha for production services, long-lived binary artifacts, package ecosystems, or compatibility-sensitive workloads.

## Installation

The command-line tools are distributed as .NET tool packages during alpha validation:

| Command | Package ID | Purpose |
|---|---|---|
| `martin` | `Martin.Tool` | User-facing project CLI for creating, building, running, formatting, cleaning, and inspecting Martin projects. |
| `martinc` | `Martin.Compiler.Tool` | Lower-level compiler-driver CLI for advanced and diagnostic workflows. |

Build local packages from the repository root:

```powershell
dotnet pack .\Martin\src\Martin.Cli\Martin.Cli.csproj --configuration Release -p:Platform=x64 -o .\artifacts\packages
dotnet pack .\Martin\src\Martin.Compiler.Cli\Martin.Compiler.Cli.csproj --configuration Release -p:Platform=x64 -o .\artifacts\packages
```

Install into an isolated tool path for validation:

```powershell
$tools = Join-Path $PWD "artifacts\tool-install"
dotnet tool install Martin.Tool --tool-path $tools --add-source .\artifacts\packages
dotnet tool install Martin.Compiler.Tool --tool-path $tools --add-source .\artifacts\packages
& "$tools\martin" --version
& "$tools\martinc" --version
```

For global personal alpha use, install from the approved package source and pin the release version when packages are published:

```powershell
dotnet tool install --global Martin.Tool --version 0.1.0-alpha
dotnet tool install --global Martin.Compiler.Tool --version 0.1.0-alpha
martin --version
martinc --version
```

See `Docs/tool-installation.md` for package inspection, local-source installation, update, uninstall, and stale-cache guidance.

```powershell
martin build

martin clean
```

A minimal Martin program:

```swift
func main() {

}
```

## Headline language features

The alpha language includes:

- Core declarations, statements, expressions, primitive literals, local variables, functions, labels, returns, `if`/`else`, `while`, scopes, arithmetic, comparison, logical operators, and `print`.
- Structs and classes with stored properties, initializers, methods, and documented value/reference semantics.
- Optional types, `nil`, optional binding, and optional patterns.
- Enums with associated values, recursive patterns, wildcard and binding patterns, literal/Boolean/optional patterns, exhaustive `switch`, and usefulness diagnostics.
- Protocol declarations, explicit conformances, requirement validation, witness maps, constrained calls, and C# interface lowering.
- Generic functions and nominal types with constructed identities, recursive substitution, type inference, constraints, code generation, formatting, and language-service support.
- Typed errors with error enums, `throws(Type)`, throwing callables, `try`, typed `do`/`catch`, exhaustiveness checking, diagnostics for unhandled throwing calls, and runtime payload preservation.

The formal source of truth for supported syntax and semantics is `Docs/specification/README.md` and its chapter files.

## Tooling and language services

`Martin.Tool` provides project-oriented workflows:

- `martin new`
- `martin build`
- `martin run`
- `martin clean`
- `martin format`
- `martin --version`

`Martin.Compiler.Tool` provides lower-level compiler-driver workflows and version reporting through `martinc`.

Compiler-backed language services include completion, hover, go-to-definition, find references, signature help, semantic classification, diagnostics, safe formatting, and editor protocol support used by Martin Studio.

## Martin Studio

Martin Studio is the WinUI-based IDE for Martin. The `0.1.0-alpha` packaging path is scoped to Windows x64.

The alpha package policy uses a stable identity:

- Identity name: `MartinLanguage.MartinStudio`
- Publisher subject: `CN=Martin Programming Language`
- Display name: `Martin Studio`
- MSIX version: `0.1.0.0`
- Architecture: `x64`

Unsigned MSIX artifacts are staging artifacts only. Release owners may sign inspected packages outside the repository with an approved certificate. Do not commit certificates, private keys, signing passwords, or publisher credentials.

See `Docs/studio-packaging.md`, `Docs/studio-build-and-run.md`, and `Docs/studio-troubleshooting.md` for package creation, signing/trust, inspection, smoke testing, and troubleshooting.

## Compatibility warning

For this alpha:

- Product and NuGet package version is `0.1.0-alpha`.
- Language version is `0.1` and cannot be selected per source file.
- Manifest schema version `1` is the only supported public schema.
- Compiler, CLI, runtime, language-service, and Studio components must come from the same release line.
- Generated C# shape and runtime helper details are not stable public APIs.
- Cross-version mixing of alpha binaries is unsupported unless a future compatibility table explicitly permits it.

Read `Docs/compatibility.md` before upgrading.

## Known limitations

Important alpha limitations include:

- `target.kind = "executable"` is the only supported public output kind; library output is rejected.
- Martin project dependency resolution and package publishing are deferred.
- Stable ABI, stable generated-output compatibility, and direct runtime-internals use are unsupported.
- Closures, extensions, modules, explicit access control, async/await, direct .NET interoperability, direct IL generation, debugger integration, and collection standard-library guarantees are deferred.
- Error unions, `try?`, `try!`, `rethrows`, and async typed errors are deferred.
- Martin Studio does not yet support multi-project solutions, integrated debugging, full terminal emulation, source-control integration, plugins, automatic updates, rename, or code actions.
- Public package upload, GitHub release publication, final tag creation, Microsoft Store publication, and certificate-backed signing require explicit release approval.

See `Docs/known-limitations.md` for the maintained limitation list.

## Upgrade instructions

Before upgrading from another alpha or local development build:

1. Read this file, `CHANGELOG.md`, and `Docs/compatibility.md`.
2. Rebuild Martin projects from source; do not reuse generated output from older alpha builds.
3. Remove or update old tool installations so `martin` and `martinc` come from the same package source and version.
4. Reinstall or upgrade Martin Studio using an artifact from the same release line.
5. Clear stale local tool caches if `dotnet tool install` resolves an unexpected version.
6. Re-run `martin --version`, `martinc --version`, and sample validation after installation.

## Uninstall instructions

For isolated tool-path installs, remove the tool directory after validation:

```powershell
Remove-Item -Recurse -Force .\artifacts\tool-install
```

For global .NET tools:

```powershell
dotnet tool uninstall --global Martin.Tool
dotnet tool uninstall --global Martin.Compiler.Tool
```

For Martin Studio, uninstall the app package through Windows Settings or `Remove-AppxPackage`. If you trusted a self-signed certificate only for Martin Studio testing, remove the corresponding `CN=Martin Programming Language` certificate from the user certificate store after uninstalling.
