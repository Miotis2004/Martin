# Security Policy

## Supported versions

Martin is pre-1.0 alpha software. Security fixes are accepted for the active development branch and the latest published alpha tag, when one exists.

## Reporting a vulnerability

Please do not open a public issue for suspected vulnerabilities.

Report security concerns by creating a private security advisory on GitHub when available, or by contacting the repository owner through the contact information listed on the project profile. Include:

- A description of the issue and affected component.
- Steps to reproduce or a proof of concept, if safe to share.
- The impact you believe the issue may have.
- Any suggested mitigation.

We will acknowledge reports as soon as practical and coordinate disclosure once a fix or mitigation is available.

## Scope

Security-relevant areas include the compiler, runtime, CLI, project-system tooling, generated project behavior, and Martin Studio. Because Martin is experimental, language and tooling behavior may change while fixes are developed.
